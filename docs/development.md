# Developer guide

## Requirements

Use Node.js 22.13 or later and npm. The root lockfile is authoritative; install from the repository root. The packages share one dependency graph.

## Local workflow

```sh
npm ci
npm run db:migrate:local
npm run build
npm run dev
```

The backend prints its local address; open `/workbench/` there. The initial fixture mode requires no provider keys to explore overview, posts, review reads, reports and Q&A. Owner mutations intentionally remain unavailable until authentication is configured.

For frontend-only edits, `npm run dev --workspace frontend` starts Vite with a same-origin API proxy to the backend on port 3000. Backend-hosted frontend assets are updated by `npm run build --workspace frontend`.

## Configuration

Copy `backend/.dev.vars.example` to the ignored `backend/.dev.vars`. Never store values in frontend environment files, screenshots, issues or commits.

| Setting | Purpose |
| --- | --- |
| `DEMO_DATA` | Explicit fictional-fixture mode; configured in the local runtime manifest |
| `WORKBENCH_ALLOWED_EMAILS` | Owner email allowlist |
| `WORKBENCH_PASSWORD_PBKDF2` | Versioned PBKDF2 password hash, never a plain password |
| `WORKBENCH_SESSION_SECRET` | At least 32 random characters for session signatures |
| `TIKHUB_API_KEY` | Server-side collection credential |
| `DASHSCOPE_API_KEY` | Server-side Qwen credential |
| `DASHSCOPE_BASE_URL / TEXT_MODEL` | Provider endpoint and text-model identifier |
| `SYNC_ENABLED / SYNC_TOKEN_V2` | Explicit machine-sync enablement and credential |
| `RESET_TOKEN_V2` | Independent destructive-reset credential; leave unset normally |
| `ANALYSIS_BACKEND_URL / TOKEN` | Optional external computation endpoint |

The password-hash format is `v1$100000$base64url-salt$base64url-derived-key`, generated by `hashPassword` in `backend/lib/email-session.ts`. Run this helper locally through a TypeScript runner or a private provisioning tool; never submit a real password to a third-party hashing website. Use a unique secret, not any test fixture value.

The standalone owner login is `/login`. Registration grants viewer privileges, not owner privileges. Owner access requires both a valid signed session and the configured allowlist. Keep `WORKBENCH_ENABLED=false` for the included standalone API; true selects the optional external-service proxy mode.

## Data and database changes

The backend runtime manifest defines local DB and object-storage bindings with placeholder resource identifiers. Local migration state lives under the ignored `backend/.wrangler` directory.

Edit `backend/db/schema.ts`, generate a migration with `npm run db:generate --workspace backend`, review the SQL, and apply it locally. Never edit an already-applied migration to change an existing database. Back up runtime state before destructive experiments.

Use `backend/lib/demo-data.ts` for reproducible fictional examples. Do not copy a private mirror or scraped payload into this tracked module. Switching away from demo mode requires complete compatible mirror objects in R2; missing data should produce an explicit error, not fabricated results.

## Quality gates

```sh
npm run typecheck
npm test
npm audit --omit=dev
npm audit
```

`npm test` builds both packages before executing backend tests. The suite exercises deterministic cleaning, aspect extraction, review-input validation, session signatures, owner authorization, source-version conflicts, mirror consistency and evaluation persistence. Compatibility tests also cover the retained enterprise storage service, although its HTTP route is retired.

Browser checks should cover: default English UI; topic navigation; positive/negative filters; post context; feedback tab; report download; evidence-linked Q&A; anonymous write denial; and owner review/evaluation after private local configuration.

External-provider calls are not part of the deterministic test suite. Validate credentials with a small authorized collection job and monitor request costs. Do not turn that check into an uncontrolled full-corpus run.

## Change discipline

Add a contract test when changing packet attributes, review vocabulary, question schemas or source signatures. Preserve raw evidence and stable identities. Treat source publication, review persistence and evaluation grading as separate lifecycle operations.
